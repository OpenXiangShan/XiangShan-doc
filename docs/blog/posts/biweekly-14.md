# 【香山双周报 14】20220801 期

欢迎来到我们的双周报专栏。本次是香山双周报专栏的第 14 期，我们将通过这一专栏，定期介绍香山的开源进展，希望与大家共同学习，一起进步。欢迎大家通过公众号后台留言的方式与我们交流！

<!-- more -->
## 近期进展

### 前端

* **优化 BPU 和 FTQ 时序**

    * 时序问题 1：推测更新 RAS 导致其扇出过大

        * 将推测更新延迟一拍同时将写操作 bypass 给读操作
        * 时序修改完成的功能调试

    * 时序问题 2：优化去除 target 寄存器

        * target 寄存器与下一预测块起始地址相同，改从 PC 寄存器堆读出并增加一单独寄存器解决 FTQ 满时无法读到下一项 PC 的问题
        * 时序修改完成的功能调试

    * 时序问题 3：去除 CommitStatusQueue

        * 一旦预测块内分支指令结果均确定即可更新 BPU，该信息可由 ROB 给出，修改正在进行

* **优化 Fetch 时序**

    * 时序问题 1：FTQ 存 pc 的寄存器到 ICache SRAM 的读口线延迟太长，有的 SRAM 太深

        * 按每 2 路拆分 8 路 SRAM，增加读口复制寄存器。FTQ 存 pc 同步读寄存器改为先读数据再锁存，复制锁存读数据的寄存器，有利于工具布线各组寄存器靠近各个读口，减少线延迟。
        * 时序修改完成的功能调试

    * 时序问题 2：ICache 流水线 tag Array 读出后进行比较产生 hit 信号锁存，这个 hit 信号用来选通 ICache 返回给 IFU 的数据是来自 SRAM（hit 情况下）还是 miss 情况（寄存器）但是 tag Array 和 data Array 距离比较远，在布局上 hit 寄存器扇出路径要绕回 data Array

        * 将 miss 和 hit 的数据以及 hit 寄存器都给 IFU，IFU 并行做指令切分和预译码，做完预译码的结果用 hit 信号来选通，代价为指令切分和预译码逻辑×4
        * 时序修改完成的功能调试

### 后端流水线

* 添加 redirect data module 备份以优化时序
* **修正 ROB 中 allowEnqueue 的判断条件**
* **优化保留站中最老指令比较逻辑以优化时序**

### 访存单元

* **昆明湖新 load 架构讨论**

    * 优化 L1 miss latency，与新的乱序调度机制联动
    * Load refill 架构优化

* **南湖时序调整**

    * 调整了跨模块逻辑级数过多的问题，降低逻辑级数到 28 以下
    * 解决了 DTLB 线延迟过高的问题
    * LSU 和 dcache 中的寄存器存在大量高扇出的问题，影响布局布线，正在用复制寄存器分摊扇出的方式解决

### 缓存系统

* 调研扣脉冲形式的 L3 半频时钟写法
* 梳理缓存代码，提炼下一版要优化的若干重点问题：

    * 请求的阻塞问题
    * Snoop/Refill 的数据存放问题
    * 通道控制器数据读写口之间的依赖问题
    * 缓存状态的形式化问题
