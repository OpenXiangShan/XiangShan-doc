# 【香山双周报 13】20220718 期

欢迎来到我们的双周报专栏。本次是香山双周报专栏的第 13 期，我们将通过这一专栏，定期介绍香山的开源进展，希望与大家共同学习，一起进步。欢迎大家通过公众号后台留言的方式与我们交流！

<!-- more -->
## 近期进展

### 前端

* **优化 BPU 和 FTQ 时序**

    * 为状态寄存器写入增加一拍延迟，增加相应 bypass 逻辑
    * 增加 ifuPtrPlus1 寄存器打断关键路径
    * 除 FTB 外预测器更新增加一拍延迟，为 FTB miss 更新增加一拍延迟
    * RAS：延迟写操作，bypass 写操作给读操作，降低扇出
    * uBTB：降低 fallThruPred 大小，使用寄存器代替 SRAM

* **优化 Fetch 时序**

    * 将 cacheline 到预测块指令码的切分逻辑进行了优化，从原来的 64 选 1 优化到 48 选一
    * 将 ICache 的 data select 从 s1 后移到 s2 优化 s1 的时序
    * 优化 PMP 产生的访问违例信号传导到 FTQ 入口端的问题
    * 优化从 ICache 的 miss 状态寄存器到 ICache 返回的 data，再到 IFU 预译码进行指令扩展的长路径问题

### 后端流水线

* **优化保留站分配 ready 信号生成时序**
* **优化大容量队列出队逻辑的设计和时序**
* **优化 ROB 时序**

    * 将 walk 与 commit valid 信号分开
    * 优化指令计数时序
    * 修正冲刷流水线时阻塞提交的条件

* **优化 dispatch2 阶段时序**

    * 将 enqOffset 与 deqPtr/enqPtr 的比较并行化
    * 在 CtrlBlock 中备份 dispatch2，避免长的跨模块环线

* **优化译码阶段时序**

    * 将软件预取指令的 decoder 移动到 rename 阶段，消除了关键路径
    * 用 X 替换将译码表中 DontCare 的信号
    * 将 fusion decoder 结果选通信号移动到 rename 阶段

* **优化并修正 OnesMoreThan 等工具函数**

### 访存单元

* **load 流水线调整到 4 拍完成，但 load 到 load 的延迟仍然为 3 拍**
* **优化跨模块交互的时序，消除从保留站重发逻辑对保留站的时序压力**
* **优化 dcache 主流水线入口处时序**
* **优化 dcache load 流水线入口处时序，消除这部分握手逻辑对保留站的时序压力**
* **优化访存违例预测器时序**
* **优化硬件性能计数器时序**
* **L1 TLB 的每个端口可以灵活的配置为阻塞式和非阻塞式**
* **修改了 DTLB 的组织形式和规模**

    * 组织形式：将内容相同的 LD TLB \*2 和 ST TLB \*2 分别合并
    * 存储形式：使用寄存器替换 SRAM
    * 容量：从全相联\*8，直接相连\*128 改为全相联\*16，直接相连\*64

### 缓存系统

* **优化 SRAM 相关的时序**

    * DataStorage：将 SRAM 读取与地址选通数据选通放到 2 拍来做
    * Directory：第一拍 SRAM 读取后计算 Way，锁存同 Set 的 Meta/Tag，第二拍做选通

* **将 L3 从 Multi-cycle Path 修改为半频**
* **定量分析缓存 Inclusion 对单核的性能影响**

### 杂项

* **DataModule 增加每个读端口的 bypass 使能控制**

## 后记

香山开源处理器正在火热地开发中，新的功能与新的优化在持续添加中，我们将通过香山双周报专栏定期地同步我们的开源进展。感谢您的关注，欢迎在后台留言与我们交流！
